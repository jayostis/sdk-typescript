# Spec diagnostics

What `npm run generate` found in the spec data it was built from: {{count}} finding(s), generated at
spec `{{commit}}`. GENERATED by `scripts/render-diagnostics.mjs` from `src/spec/diagnostics.json`
through `scripts/templates/diagnostics.md`; do not edit — it is rebuilt with `src/spec/`, and
nothing here is committed or shipped.

**Grouped by owner first**, because the first thing a reader needs is whether a row is theirs at all:
`spec` rows are the ones to paste upstream, `sdk` rows are this repository's, `reconcile` rows are a
question to answer before anyone knows whose fix it is. Severity second — `error` blocks conversion
today, `warning` is silently wrong or silently guessed at runtime, `info` is hygiene or an open
question. Every row carries its **code**, and every code heading links the entry in
[`docs/spec-diagnostics.md`](../../docs/spec-diagnostics.md) that says what the finding means, which
files to open, why it needs a decision, and what makes the row go away. The 📄 paths are the files
to open: `spec:` relative to a `spec` checkout, `sdk:` relative to this repository.

A row's id is `code:subject` and is the same across builds, so the same defect at two spec
revisions compares equal.
